# Проверка RC-переключения режимов C-20T

Это экспериментальные прошивки для проверки кодов режима 0/1/2 в существующем UART-пакете INAV A5 5A (10 байт). Их соответствие пресетам M0/M1/M2 и семи режимам C-20T не подтверждено. Новые значения 3–7 RC-переключатель не отправляет.

## Настройка

Сохраните текущую конфигурацию контроллера. Установите HEX строго своего target, сохраните используемые настройки UART подвеса и его каналов осей. По умолчанию новый канал отключён, текущее управление режимами сохраняется.

Для трёхпозиционного переключателя на CH8 (AUX4):

```
set gimbal_mode_channel = 8
save
```

Можно выбрать канал 1–34, но он должен действительно присутствовать в сигнале приёмника. Поле канала добавлено в исходники Configurator; для проверки с ранее собранным Configurator используйте CLI.

Нижнее / среднее / верхнее положение отправляет код 0 / 1 / 2. Номинальные границы — 1300 и 1700 мкс, гистерезис — 40 мкс в каждую сторону, подтверждение положения — 150 мс. При некорректном сигнале, отсутствующем канале или потере связи немедленно выбирается код 0. Это не гарантирует Follow: если коды выбирают пресеты, настройте M0 как FPV/Follow в GimbalConfig.

Center и Headtracker принудительно выбирают прежний код Follow (0) с приоритетом над RC-каналом. Команды осей и поведение осей Center/Headtracker сохранены, включая существующее поведение при их одновременном включении. При назначенном канале Level Tilt/Roll не определяют поле mode; при значении 0 всё работает как прежде.

Отключить экспериментальный выбор:

```
set gimbal_mode_channel = 0
save
```

## Последовательность стендовой проверки

1. Снимите пропеллеры. Запишите версию прошивки C-20T, подключение UART и текущие назначения M0/M1/M2 в GimbalConfig.
2. При канале режима 0 проверьте прежнюю работу осей, Center, Headtracker и Level Tilt/Roll.
3. Убедитесь, что выбранный RC-канал показывает примерно 1000 / 1500 / 2000 во вкладке приёмника. Отключите Center и Headtracker, включите канал режима.
4. Последовательно установите нижнее, среднее и верхнее положения. Запишите фактическое поведение подвеса для каждого положения.
5. Если возможно, измените назначения M1/M2 в GimbalConfig и повторите проверку. Только если фактические режимы следуют новым назначениям, можно подтвердить, что UART-коды выбирают пресеты, а не жёстко заданные режимы.
6. Во время переключения двигайте оси: выбор режима не должен менять отправляемые команды осей. Особенности интерпретации угла/скорости зависят от выбранного режима самого подвеса.
7. Включите Center, затем отдельно Headtracker: их прежнее управление должно иметь приоритет. Выключите — выбранный режим вернётся после 150 мс стабильного RC-сигнала.
8. Выключите передатчик и проверьте возврат к поведению кода 0. Если приёмник вместо признака failsafe продолжает выдавать удержанные корректные каналы, INAV не сможет отличить такое удержание от живого сигнала.
9. Перезапустите контроллер: настройка канала должна сохраниться. При обновлении с версии группы настроек 1 каналы осей, чувствительность и тримы переносятся, новый канал равен 0.

Для отчёта нужны: target контроллера, версия C-20T, назначения M0/M1/M2 и наблюдаемое поведение нижнего / среднего / верхнего положения, результат после изменения пресетов и потери связи.

## Совместимость

- Размер, заголовок, упаковка осей, чувствительность, алгоритм CRC и частота UART-обмена не изменены.
- Группа PG_GIMBAL_CONFIG повышена с версии 1 до 2 с переносом старых полей.
- Это стендовая проверка совместимости; подтверждение на реальном C-20T требуется перед включением функции в релиз.
